# Azure deployment boundary

This module is intentionally fail-closed: `enable_apply` defaults to `false`, so a plan contains no resources until an operator explicitly supplies the gate. When enabled it creates a public web Container App, an internal API Container App reached only through the web same-origin proxy, a queue-triggered worker Job, a migration Job, network-private versioned Blob storage and Service Bus queue with dead-lettering (private endpoints, dedicated subnet, and private DNS), a VNet-integrated Container Apps environment, delegated private PostgreSQL subnet/private DNS, Key Vault secret reference, managed identities/RBAC, health probes, scale bounds, and App Insights. The Terraform backend is configured by protected workflow inputs; no state storage or credentials are checked in. Separate Entra SPA and API client IDs are passed to the web/API cloud boundary, with bearer validation enabled for the API.

Required apply inputs are immutable `container_image`, `web_image`, `postgres_admin_password`, and Entra identifiers; there are no fake defaults. `terraform validate` and `fmt` are safe local checks. Apply and destroy are only implemented by the protected OIDC workflows.
