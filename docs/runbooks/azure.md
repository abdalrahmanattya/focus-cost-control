# Azure ephemeral runbook

The protected workflows require `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `POSTGRES_ADMIN_PASSWORD` (at least 16 characters), pinned `CONTAINER_IMAGE` and `WEB_IMAGE` digests, `ENTRA_TENANT_ID`, separate `ENTRA_SPA_CLIENT_ID` and `ENTRA_API_CLIENT_ID` values, `ENTRA_OPERATOR_GROUP_ID`, and Terraform state variables (`TF_STATE_RESOURCE_GROUP`, `TF_STATE_STORAGE_ACCOUNT`, `TF_STATE_CONTAINER`, `TF_STATE_KEY`) in the GitHub environment. The SPA client is used only by MSAL; the API client is used only for JWT audience and `api://<api-client-id>/user_impersonation` scope. The images are supplied as immutable digests; no password or image default is checked in.

Run `azure-plan` with `PLAN-ONLY`, then use the protected `azure-apply` environment approval for `APPLY-APPROVED`. The plan intentionally evaluates the real graph with `enable_apply=true`; it still performs no mutation. Apply creates a public web Container App and internal API, runs the one-shot migration Job before smoke, and derives the web URL from Terraform output. The web proxy keeps API traffic same-origin and the SPA obtains a Microsoft Entra bearer token through MSAL. `azure-smoke` calls the public web URL, imports the synthetic fixture, polls completion, checks dedupe/analytics/allocation/unit economics, and captures only sanitized evidence. `azure-destroy` removes the temporary resource graph and asserts the target resource group is absent. No workflow runs automatically.
